# Where each lane stands against upstream

Re-checked on 2026-10-09 against the GitHub API, the cookbook and inside the images rather than against dates, and re-measured on the box before any conclusion. Moved out of the README in v1.14.2.

Since 2026-08-21, this same combination (DFLASH2, draft depth 16 since v1.9) is the **official recipe in the [SGLang cookbook](https://docs.sglang.io/cookbook/autoregressive/Qwen/Qwen3.8-27B)**, and since v1.14 this repo serves an official release image on that lane, with no overlay built on top: `v0.5.21` since v1.23 (`v0.5.19` before it). It held out until 2026-09-17 over the mrope fix ([sglang#34446](https://github.com/sgl-project/sglang/pull/34446), the fused Qwen3.5 RoPE kernel discarding mrope height and width), which merged 2026-08-30 and is in the release; checked in the image rather than assumed. Neither lane builds anything on top of its image: the 27B serves a release, the flash lane a nightly, both from `lmsysorg/sglang` and pinned by digest.

**Where each lane stands against upstream, re-checked on 2026-10-09 against the GitHub API and inside the images rather than against dates:** the 27B lane serves the official `v0.5.21` release since v1.23 (it carries the DFlash checkpoint fix [sglang#37818](https://github.com/sgl-project/sglang/pull/37818) that `v0.5.19` lacked; each move cost a full bench, concurrency and long-context cycle on this box, the numbers are in the CHANGELOG). The flash lane serves `nightly-cu134-20260928-6caf0ff`, pinned by digest (`cb6ed363`), since v1.19, measured here on 2026-09-29 against the image it replaced, same tier, same probes: greedy median 46.9 against 46.2 tok/s, `conc-check` 40/40 serial and 80/80 at concurrency 4, needle exact at 120,196 and 199,920 prompt tokens. The previous image (`4ccff141d`, the head of `qwen4-main-squashed`) already ran the DGX Spark stack this lane needs (the file-backed PLE table of [#37068](https://github.com/sgl-project/sglang/pull/37068), the NVIDIA mixed-precision loader, the PDL router fix, the TP prefetch correction), which [#39126](https://github.com/sgl-project/sglang/pull/39126) brought into `main`; what `6caf0ff` adds, each checked as an ancestor of it with the GitHub compare API: three correctness fixes in the QSA sparse-attention kernels this lane provably uses ([#38855](https://github.com/sgl-project/sglang/pull/38855), [#38851](https://github.com/sgl-project/sglang/pull/38851), [#38346](https://github.com/sgl-project/sglang/pull/38346)), and [#39474](https://github.com/sgl-project/sglang/pull/39474), whose title says it stops "endlessly creating streams" but whose four lines only move the QSA top-k launch, on the alternate stream the model already holds, from before the QKV preparation to *after* it: an overlap change, not a leak fix. Upstream on 2026-10-09: the cookbook still points DGX Spark at `dev-qwen38-next-local` (digest `9d2a843c`, unchanged since 2026-09-07, built from `4ccff141db`) and measures its single-Spark cells on that build, while its B200, B300 and GB300 cells for the NVIDIA export point at release images. `v0.5.21` contains `6caf0ff` and 49 later commits, among them the Rust radix tree as the default ([#39627](https://github.com/sgl-project/sglang/pull/39627)), but ships a CUDA 13.0 image only (`v0.5.21`, `v0.5.21-cu130` and `latest` are one image), where this lane runs the CUDA 13.4 nightlies; the latest of those, `nightly-cu134-20261009-91b3692`, also carries #39627 and [#40987](https://github.com/sgl-project/sglang/pull/40987), which updates DeepGEMM, DeepEP and sgl-kernel in that image and rebases it on a CUDA base image. Either is a new measurement on this box before any switch, the same cycle as the 27B's. Two upstream bugs on this model are still open: NEXTN acceptance decaying towards zero over server uptime ([#37326](https://github.com/sgl-project/sglang/issues/37326)) and a chunked-prefill and radix-insert race that corrupts KV pages under QSA ([#38319](https://github.com/sgl-project/sglang/issues/38319)).
